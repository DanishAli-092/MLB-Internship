## 🧠 Concepts

### What is Clustering?
Clustering is an unsupervised technique that groups data points together based on how
similar they are to each other, without using any predefined labels. The algorithm looks
purely at the feature values and decides which points "belong together." It's used in
customer segmentation, anomaly detection, document grouping, and recommendation systems.

### How K-Means Works
1. Pick a number of clusters, **K**.
2. Randomly place K centroids.
3. Assign every point to its nearest centroid.
4. Recalculate each centroid as the mean of the points assigned to it.
5. Repeat steps 3–4 until centroids stop moving (convergence).

Because K-Means relies on distance, all features were **standardized** (mean 0, std 1)
before clustering — otherwise a feature measured in larger units would unfairly dominate
the distance calculation. Note that the `species` column is **never** shown to K-Means —
it's dropped before fitting. It's only reattached *after* clustering, purely to sanity-check
how well the unsupervised groups line up with the real species — something only possible
here because Iris happens to be a labeled teaching dataset.

### How I Determined the Best Value of K (Elbow Method)
I ran K-Means for K = 1 through 10 and recorded the **WCSS (Within-Cluster Sum of
Squares / inertia)** for each — a measure of how tightly packed the points are around
their centroid. As K increases, WCSS always decreases, but after a certain point the
improvement becomes marginal. Plotting WCSS against K produces a curve that visibly
bends at that point — the "elbow." For the Iris dataset, the elbow appears clearly at
**K = 3**, which also happens to match the real number of species (setosa, versicolor,
virginica) — a nice confirmation that the elbow method picked something meaningful, not
just a random number.

### What is PCA?
Principal Component Analysis (PCA) is a dimensionality reduction technique. It takes
data with many correlated features and re-projects it onto a smaller number of new axes
("principal components") that capture the maximum possible variance in the data. The
first component captures the most variance, the second captures the next most (while
being uncorrelated with the first), and so on. This makes it possible to visualize
high-dimensional data in 2D or 3D, speed up model training, and reduce noise/redundancy
between correlated features.

For the Iris dataset (4 features), reducing to 2 principal components retained
**~95.8% of the total variance** — meaning almost none of the "information" in the data
was lost, even though we cut the number of dimensions in half.

## 📊 Insights from the Visualizations

- **Cluster vs. species alignment:** Comparing the K-Means clusters against the true
  species labels (only possible here because Iris is a labeled teaching dataset), the
  clusters lined up with the real species in roughly **83%** of cases.
- **Setosa is trivially separable** — it forms its own tight, clearly isolated cluster
  in both the raw feature scatter plot and the PCA projection. This matches the known
  biology: setosa is morphologically quite different from the other two species.
- **Versicolor and virginica overlap somewhat** in both the clustering and the PCA plot,
  because they are genuinely more similar to each other in petal/sepal measurements.
  K-Means occasionally misassigns points between these two clusters near the boundary.
- **PCA didn't distort the story** — the shape of the clusters in the 2D PCA plot closely
  mirrors the shape seen in the original petal length vs. petal width scatter plot. This
  confirms that reducing to 2 dimensions preserved the meaningful structure in the data
  rather than hiding it.

## 🖥️ Streamlit App Features

The app (`app.py`) goes beyond the minimum requirement:

- **Upload your own dataset** (CSV or Excel) *or* use the built-in Iris dataset.
- **Automatic detection of numeric columns**, with the option to pick which features
  to cluster on and (optionally) color points by a categorical label column.
- **Live Elbow Method chart** — the K slider lives in the sidebar, so a dashed marker
  on the elbow curve tracks your chosen K in real time as you drag it, before you even
  run K-Means.
- **On-demand K-Means and PCA** via explicit "Apply" buttons, so expensive
  recomputation only happens when you actually want it — not on every widget interaction.
- **Silhouette Score** reported alongside WCSS, to quantify how well-separated the
  clusters actually are (not just visually, but numerically).
- **Cluster centroids plotted directly on the data** (as black "X" markers), in both
  the original feature space and the PCA-projected space — inverse-transformed back
  into real feature units so they sit correctly on the same axes as the data points.
- **PCA feature loadings heatmap**, showing which original features drive each
  principal component and by how much.
- **3D scatter plots** of both the raw feature space and the PCA projection (when 3+
  features are selected).
- **Dimensions before vs. after PCA**, reported as a live metric.
- **Download button** to export the clustered dataset as a CSV.
- **Stale-result protection**: if you change the dataset, feature selection, or K after
  already running K-Means/PCA, the app detects the mismatch and asks you to re-run
  instead of silently showing (or crashing on) outdated results — see the Issues
  section below for why this matters.

## 🐞 Issues Faced & How They Were Fixed

Documenting these because debugging them was as much a part of today's learning as the
K-Means/PCA theory itself.

**1. `ModuleNotFoundError: No module named 'plotly'`**
The app uses Plotly for the interactive 3D charts, which isn't part of the Python
standard library. Fixed by adding `plotly` to `requirements.txt` and running
`pip install -r requirements.txt` before launching the app.

**2. Pairplot title overlapping its subtitle**
An early version of `style_config.py` positioned the subtitle using a hardcoded
figure coordinate (`y=0.995`) independent of where the main title (`y=1.02`) landed,
so on the 4×4 pairplot the two text elements collided. Fixed by adding an
`add_figure_title()` helper that always places the subtitle a fixed relative offset
*below* the title, so they can never overlap regardless of figure size.

**3. `ValueError: X has N features, but PCA is expecting M features` (the big one)**
This surfaced when uploading a custom dataset after already running K-Means/PCA on the
built-in Iris data. Root cause: the app lets K-Means and PCA be applied independently
via separate buttons, and each result is cached in `st.session_state`. If the feature
selection changes (e.g. switching datasets) and only one of the two is re-applied, the
cached model from *before* the change gets used against data shaped for *after* the
change — e.g. a PCA model fit on 4 columns being asked to `.transform()` a 5-column
array. This is a classic **stale-state bug** in Streamlit apps that use
`st.session_state` to avoid recomputing on every rerun.

Fixed by fingerprinting every cached result with `(selected_features, row_count)` at
the time it was computed, then explicitly checking that fingerprint against the
*current* selection before reusing the result anywhere — in the K-Means tab, the PCA
tab, *and* the summary tab (all three had the same class of bug). If they don't match,
the app shows a warning asking the user to re-run instead of silently using — or
crashing on — mismatched data.

**4. Silent caching bug avoided (`st.cache_data` with an underscore-prefixed argument)**
While comparing approaches, I found that prefixing a cached function's only argument
with an underscore (e.g. `def compute_wcss(_scaled_features)`) tells Streamlit to
*exclude* that argument from the cache key — meaning the function would keep returning
results computed from whatever dataset was passed in *first*, even after switching to a
completely different dataset. Avoided this entirely by not underscore-prefixing any
argument that the cache correctness actually depends on.
